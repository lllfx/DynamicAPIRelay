API 中转使用说明

把你要调用的海外 API 地址放进请求头，发到本中转，中转替你请求并把结果原样返回。新增目标网站不需要改任何配置。

快速开始请求格式示例怎么判断结果错误码限制注意事项

快速开始

中转地址：{{.Base}}/v1/relay。你需要一个中转 key，向管理员申请，每人一个，不要转发给别人。

curl '{{.Base}}/v1/relay' \
  -H 'X-Relay-Key: 你的中转key' \
  -H 'X-Relay-Target: https://api.github.com/zen'

返回的就是 https://api.github.com/zen 的响应内容。

请求格式

把原来发给目标 API 的请求原样发给中转，只做两处改动：

  1. 请求地址改成 {{.Base}}/v1/relay（后面不要加任何路径或 ? 参数）。
  2. 加两个请求头：X-Relay-Key 和 X-Relay-Target。
项目说明
X-Relay-Key必填。中转 key，只用于中转鉴权，不会发给目标 API。
X-Relay-Target必填。目标 API 的完整地址，包括路径和查询参数，例如 https://api.example.com/v1/chat?stream=true。不会发给目标 API。
请求方法与目标 API 一致：GET、HEAD、POST、PUT、PATCH、DELETE。
Authorization、x-api-key 等目标 API 自己的认证头，照常带上，中转会原样转发给目标。
请求体原样转发，JSON、表单、文件上传、二进制都可以。

示例

JSON POST（目标 API 有自己的 token）

curl '{{.Base}}/v1/relay' \
  -X POST \
  -H 'X-Relay-Key: 你的中转key' \
  -H 'X-Relay-Target: https://api.example.com/v1/chat' \
  -H 'Authorization: Bearer 目标API的token' \
  -H 'Content-Type: application/json' \
  --data-binary '{"message":"hello"}'

流式输出（SSE）

curl -N '{{.Base}}/v1/relay' \
  -X POST \
  -H 'X-Relay-Key: 你的中转key' \
  -H 'X-Relay-Target: https://api.example.com/v1/stream' \
  -H 'Content-Type: application/json' \
  --data-binary '{"stream":true}'

上传文件

curl '{{.Base}}/v1/relay' \
  -H 'X-Relay-Key: 你的中转key' \
  -H 'X-Relay-Target: https://uploads.example.com/v1/files' \
  -F 'file=@./demo.pdf' -F 'purpose=review'

下载文件

curl '{{.Base}}/v1/relay' \
  -H 'X-Relay-Key: 你的中转key' \
  -H 'X-Relay-Target: https://files.example.com/releases/archive.zip' \
  -o archive.zip

Python（requests）

import requests

RELAY = "{{.Base}}/v1/relay"
RELAY_KEY = "你的中转key"

def relay(method, target_url, **kwargs):
    headers = kwargs.pop("headers", {})
    headers.update({"X-Relay-Key": RELAY_KEY, "X-Relay-Target": target_url})
    # allow_redirects=False：中转不跟随重定向，客户端也不要自动跟随
    return requests.request(method, RELAY, headers=headers, allow_redirects=False, **kwargs)

resp = relay("POST", "https://api.example.com/v1/chat",
             headers={"Authorization": "Bearer 目标API的token"},
             json={"message": "hello"}, timeout=120)
if resp.headers.get("X-Relay-Error") == "true":
    print("中转报错:", resp.json()["error"])   # 见下方错误码
else:
    print(resp.status_code, resp.text)       # 目标 API 的原始响应

# 等价写法：requests.post(RELAY, headers={...}, json={...})

JavaScript / Node.js（fetch）

const resp = await fetch("{{.Base}}/v1/relay", {
  method: "POST",
  redirect: "manual",
  headers: {
    "X-Relay-Key": "你的中转key",
    "X-Relay-Target": "https://api.example.com/v1/chat",
    "Authorization": "Bearer 目标API的token",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ message: "hello" }),
});
if (resp.headers.get("X-Relay-Error") === "true") {
  console.error("中转报错:", (await resp.json()).error);
} else {
  console.log(resp.status, await resp.text());
}

请在服务端或命令行使用，不要把中转 key 写进浏览器前端代码。

怎么判断结果

  • 响应头 X-Relay-Error: true：是中转自己拒绝或出错，响应体是 JSON，格式见下方错误码。
  • 没有这个头：就是目标 API 的原始响应，状态码、响应头、内容都原样透传。比如目标返回 401，说明是目标 API 的 token 有问题，不是中转 key 的问题。
  • 每个响应都带 X-Relay-Request-ID。遇到问题时把它发给管理员，可以直接查到这次请求。
{"error":{"code":"TARGET_FORBIDDEN","message":"Destination is not allowed","request_id":"req_..."}}

错误码（仅在 X-Relay-Error: true 时）

状态码错误码原因与处理
400TARGET_INVALID没带 X-Relay-Target，或地址格式不对（不是完整 URL、含空格或 #、百分号编码错误等）。
400REQUEST_INVALID中转地址后面带了路径或 ? 参数、重复写了 X-Relay-Target，或使用了 WebSocket/Upgrade。
401AUTH_FAILED中转 key 缺失或错误。
403TARGET_FORBIDDEN目标不允许：不是 https、用了 IP 地址或非 443 端口、或域名解析到内网地址。
404NOT_FOUND中转地址写错了，应为 /v1/relay。
405METHOD_NOT_ALLOWED不支持的请求方法（如 OPTIONS、TRACE）。
413REQUEST_TOO_LARGE请求体超过上限（见下方限制）。
429RATE_LIMITED请求太快，稍后重试。
429CONCURRENCY_LIMITED同时进行中的请求太多，等前面的完成再发。
502UPSTREAM_CONNECT_FAILED连不上目标：域名不存在、拒绝连接或证书错误。
502UPSTREAM_PROTOCOL_ERROR目标返回了无效响应，或响应超过大小上限。
504UPSTREAM_TIMEOUT目标在限定时间内没有开始响应。

如果响应已经开始输出（例如流式传输到一半）后才出问题，没法再返回错误 JSON，连接会直接断开。

注意事项

  • 目标要求：只能是 https://、用域名（不能是 IP）、端口为 443 或不写、且解析到公网地址。
  • 不跟随重定向：目标返回 301/302 等时，中转原样返回。如需继续，请用 Location 里的新地址再发一次中转请求，客户端不要自动跟随。
  • 不支持 WebSocket、gRPC、HTTP CONNECT 代理。这是 API 中转，不是 VPN 或网页代理，浏览网页、Cookie、跨域等不保证可用。
  • 不自动重试：失败是否重试由你自己决定，尤其是会产生副作用的 POST 请求。
  • 保管好 key：中转 key 等同于使用权限，不要提交到代码仓库或发到群里。泄露了请联系管理员更换。
⚠️ 当前访问地址是 {{.Base}}。如果是 http://，中转 key、目标 API 的 token 和请求内容在网络上都是明文传输，可能被截获。请不要通过它发送高敏感数据，并尽量在可信网络中使用。
